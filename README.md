# TSYS EDC (POS 5.3) File Comparator

A layout-driven Java tool that compares a **production** TSYS EDC (POS 5.3)
file against a **test** version and reports differences in content, length,
and missing/extra records — while ignoring record row/position and specific
fields you mark as ignorable (e.g. the Batch Header sequence number).

## Design: key-based matching + positional diff (no field dictionary needed)

Given that transaction records can carry 100+ fields across many transaction
sub-types, this tool does **not** require you to name every field. Instead:

- **Matching**: each record type declares where its unique key lives (for
  Transaction Detail records, the **RRN** at position 122, length 12). Two
  records are matched purely by that key — never by row number. **A record
  found on a different row in the test file than in production is matched
  correctly and is NOT reported as a mismatch just because it moved.**
  Record types with no natural key (a single Batch Header / Batch Trailer /
  File Header / File Trailer per file) are matched by occurrence order
  instead, since there's nothing else to key on.
- **Differencing**: once two records are matched, the two raw lines are
  compared **character by character** (skipping any declared ignore zones).
  Contiguous runs of differing characters are grouped into a single reported
  difference: position, length, production value, test value. This still
  tells you exactly *where* and *what* differs — you just don't have to
  pre-declare a name for every byte range.
- **Ignore zones**: fields that are expected to legitimately differ (e.g. the
  Batch Header sequence number at position 3, length 4) are declared once per
  record type and are skipped entirely during comparison.

The comparison engine (`EdcFileComparator`) never needs to change when the
layout changes — only `sample-data/layout-config.csv` does.

## IMPORTANT — layout is still provisional

The record type codes (`FH`, `BH`, `TXV`, `BT`, `FT`) and the RRN position
(122–133) reflect a photographed screen, not a verified file. Once you supply
the actual file (or confirm positions from the CSV/exported text), update
`sample-data/layout-config.csv` — no other changes are needed.

## Configuration format (`layout-config.csv`)

```
recordType,recordTypeName,keyStart,keyLength,ignoreZones
FH,File Header,0,0,
BH,Batch Header,0,0,3:4
TXV,Transaction Detail,122,12,
BT,Batch Trailer,0,0,
FT,File Trailer,0,0,
```

- `keyStart,keyLength` — 1-based position/length of the record's unique key
  (e.g. RRN). Use `0,0` for record types with no natural key.
- `ignoreZones` — `start:length` pairs separated by `|` (e.g. `3:4|50:2`).
  Leave blank if nothing should be ignored for that record type.
- Record types are identified by **prefix match** against the start of each
  line (longest registered code tried first), so mixed-width type codes
  (`BH` at 2 chars, `TXV` at 3 chars) coexist fine in the same file.
- Unmapped lines are still captured as type `UNKNOWN` and shown in the report
  rather than silently dropped.

## Performance

Parsing uses a `BufferedReader` (line-at-a-time), and matching uses
`HashMap`-based key lookups — O(n) overall, so 10,000+ records per file is
handled comfortably. There is no O(n²) record-vs-record loop anywhere.

## Build

Requires JDK 11+ (uses `String.repeat`; nothing else needs newer than 8).
No external dependencies — pure `java.*` standard library.

```bash
cd edc-compare
mkdir -p out
javac -d out $(find src -name "*.java")
```

## Run

```bash
# Using the bundled sample layout:
java -cp out com.bank.edccompare.Main sample-data/prod.txt sample-data/test.txt

# Using an external layout CSV (recommended once the real spec is confirmed):
java -cp out com.bank.edccompare.Main /path/prod.txt /path/test.txt sample-data/layout-config.csv /path/to/output-dir
```

Arguments:
1. Production file path (required)
2. Test file path (required)
3. Layout CSV path (optional — defaults to the bundled sample layout)
4. Output directory for reports (optional — defaults to current directory)

## Output

- **Console**: a summary table (per record type: prod/test counts, matched,
  missing, extra, records-with-differences) plus an overall PASS/FAIL verdict.
- **`comparison_report.txt`**: full structured report — summary, missing
  records, extra records, content differences (with position/length/values),
  and duplicate-key warnings.
- **`differences.csv`**: the same differences in CSV form, for filtering/
  sorting in Excel when there are many rows.

Exit code: `0` = PASS, `2` = FAIL (differences found), `1` = error.

## Sample data included

`sample-data/prod.txt` and `sample-data/test.txt` (generated by
`sample-data/gen_sample.py`) deliberately exercise every requirement:
- Batch Header sequence number differs between files → **ignored**, no diff reported.
- Two Transaction Detail records (RRN `...0001` and `...0002`) are on
  **different rows** between the two files → matched correctly by RRN,
  **no false mismatch from the row change alone**.
- RRN `...0003` exists only in production → reported **MISSING**.
- RRN `...0005` exists only in test → reported **EXTRA**.
- RRN `...0004` has changed content and a different overall line length in
  test → reported as a **content difference** plus a **line length mismatch**.

## Project structure

```
src/com/bank/edccompare/
  Main.java                      CLI entry point
  config/RecordTypeRule.java     one record type's key position + ignore zones
  config/LayoutRepository.java   registry, CSV loader, sample layout, type ID by prefix
  model/ParsedRecord.java        one parsed line + its extracted key
  parser/EdcFileParser.java      streaming line-by-line file parser
  compare/EdcFileComparator.java core matching/diffing engine (key match + positional diff)
  compare/*.java                 result model classes (differences, summary, report)
  report/ReportWriter.java       console / text / CSV report generation
```
